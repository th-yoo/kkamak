**Context.** kkamak is a completion gate for Claude Code: a `Stop` hook runs a
repo-configured check and blocks the turn until it passes. The first public
release is 0.4.0. Already landed on this branch, do not redo:

  13 tests, `--gauge` dropped (`8634216`).

  README sensor sample; publisher metadata on plugin.json (`aec2886`).
- README rewritten CC-first with a real install path, a write-surface
  statement, and `docs/opencode.md` for the experimental adapter (`afbd9f2`).

Suite is 309 tests, `bun test`, plus `bunx tsc --noEmit`. Both green at
`afbd9f2`.

## Task 3 — Install verification runbook

Write `docs/install-verification.md`: the exact procedure a maintainer runs to
prove a release is installable, to be executed by a human on a real machine
after the tag is pushed. This task authors the runbook; it does not run it.

Requirements:

- The two install commands (`claude plugin marketplace add th-yoo/kkamak`,
  `claude plugin install kkamak@kkamak`) and what success looks like.
- A cache verification step: after install, grep the installed plugin cache
  for the files this release adds — the init CLI and the command file — and
  confirm exactly one version directory is present. Installed plugins live
  under `~/.claude/plugins/cache/`. The point is proving the running copy is
  the new one, since the install is a copy, not a live reference.
- A live block proof: create a scratch repo, write a `gate.json` whose check
  fails on purpose, edit a file in a Claude Code session, end the turn, and
  observe a real block. Include the sensor line as the durable evidence
  (`.km/gate-outcomes.ndjson`, `pluginVersion` must read `0.4.0`).
- A prominent warning: reinstalling deletes the plugin's cache root, which
  kills hooks fail-open in any Claude Code session running at that moment.
  Do not reinstall while a session you care about is live.
- A cleanup step that removes the scratch repo.
- State plainly that until this runbook has been executed on a real machine,
  the release is unproven — a green test suite does not demonstrate
  installability.

Verification: every command in the runbook must be one a reader can paste.
Do not include a command you have not confirmed the syntax of; where you are
unsure of exact output, describe what to look for rather than inventing a
transcript.
